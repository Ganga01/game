# Свояк — своя компания

Версия 1.1: новый облегчённый набор вопросов. Для бесплатного размещения выбран **Render** — инструкция ниже. Домашний компьютер во время игры не нужен.

Мобильная сетевая викторина для 2–12 игроков и отдельного ведущего. Все пользуются браузерами на своих телефонах. Во время игры компьютер не нужен: Node.js работает на удалённом сервере.

Новые авторские формулировки, шуточные описания и вопросы-ловушки. Это самостоятельная игра, не копия конкретного выпуска YouTube. В комплекте 120 вопросов: 2 раунда по 12 тем, в каждой теме 5 вопросов. Перед созданием комнаты можно выбрать 30, 60, 90 или 120 вопросов.

## Что готово

- Создание комнаты, шестизначный код и ссылка для приглашения.
- Выбор максимального числа игроков: 2–12. Можно начать от двух, не заполняя комнату.
- Ведущий управляет вопросами и оценивает устные ответы с телефона.
- У игроков большая кнопка. Победитель нажатия определяется сервером.
- После ошибки игрок теряет стоимость вопроса и не может отвечать на этот же вопрос повторно; остальные могут нажать.
- 30 секунд на нажатие, 30 секунд на устный ответ. Таймер ведёт сервер.
- После истечения времени ответа — автоматический штраф. Если никто не нажал, штрафа нет.
- Ведущий может отменить последнюю оценку, пока не произошло следующее нажатие или переход.
- Цена вопросов: 100–500 в первом раунде, 200–1000 во втором.
- Результаты, ничьи, досрочное завершение, возврат в свою сессию.
- Ответы и будущие вопросы не передаются игрокам заранее. Ведущий видит подсказку.
- Автоматическое восстановление соединения и сохранение состояния комнаты на диске.

## Как играть — только с телефонов

1. Ведущий открывает адрес развёрнутого сайта, выбирает «Я ведущий», количество мест и раундов.
2. Нажимает «Создать комнату», затем «Пригласить друзей» или «Копировать».
3. Каждый игрок открывает ссылку на своём телефоне, вводит имя. При ручном входе выбирает «Я игрок» и вводит код.
4. Ведущий нажимает «Все на месте. Начать». Ведущий не входит в число 2–12 игроков.
5. Игрок с пометкой «выбирает вопрос» называет тему и стоимость вслух; ведущий открывает ячейку.
6. Ведущий читает вопрос, затем нажимает «Открыть кнопки». До этого нажатия не принимаются.
7. Первый нажавший отвечает вслух. Ведущий выбирает «Верно» или «Неверно». После правильного ответа этот игрок выбирает следующий вопрос.
8. После раскрытия ответа ведущий нажимает «Дальше».

Для компании в разных местах нужен отдельный голосовой звонок: встроенного аудио/видео нет.
Не сворачивайте браузер во время вопроса: мобильная ОС может приостановить вкладку. После возврата состояние подтянется автоматически.
При обновлении страницы нажмите «Вернуться в комнату». Используйте тот же браузер: ключ роли хранится в нём. В приватном режиме после закрытия вкладки восстановление может быть невозможно.
Один браузер хранит последнюю сессию. Для нескольких ролей на одном устройстве используйте разные браузеры. Ведущий не должен отправлять свой ключ сессии: кнопка приглашения копирует только общую ссылку.

## Быстрый запуск для проверки

Нужен Node.js 22 или новее. Внешних npm-зависимостей нет.

```sh
npm ci
npm test
npm start
```

Откройте http://localhost:3000. Для телефона в той же Wi-Fi-сети: `http://IP-КОМПЬЮТЕРА:3000` (при необходимости разрешите порт в брандмауэре). Это только вариант локальной проверки. Для игры без компьютера разместите проект на хостинге ниже.
Копирование в буфер обмена и системная кнопка «Поделиться» зависят от HTTPS/поддержки браузера; ссылка всегда показана текстом.

## Выбранный бесплатный вариант: Render

1. Распакуйте архив и загрузите содержимое папки `svoyak` в GitHub-репозиторий, сохранив папки `public`, `src`, `data` и `test`. `package.json` должен быть в корне репозитория. Загружайте файлы проекта, а не ZIP.
2. На https://render.com создайте **Web Service**, подключив репозиторий. **Static Site не подходит**: игре нужен работающий сервер.
3. Выберите Node runtime, Build Command `npm ci`, Start Command `npm start`, Free plan. Версия Node — 22. Если выбираете Docker runtime, используйте прилагаемый Dockerfile.
4. Health check: `/health`.
5. Дождитесь развёртывания, откройте выданный HTTPS-адрес на телефонах.

В комплекте есть `render.yaml`, если удобнее создать сервис через Blueprint.

Ограничения бесплатного Render: после 15 минут без входящего трафика сервис засыпает, первый запуск занимает около минуты. Файлы на локальном диске исчезают при перезапуске, повторном развёртывании или засыпании. Поэтому активная комната может потеряться, а сохранённый в браузере ключ перестанет работать. Для пробной партии подходит, для мероприятия с важными результатами лучше постоянный диск на платном тарифе или VPS. Бесплатный Render также может перезапускаться по инициативе платформы.

Источник: https://render.com/docs/free


## Дополнительный платный вариант: Railway

Для постоянной игры удобнее платный Railway с постоянным диском. По проверенной на 25.10.2026 информации план Hobby начинается с $5/месяц, включает $5 потребления ресурсов; расход сверх включённого оплачивается отдельно. Это не гарантия фиксированного счёта. Проверьте актуальный тариф и настройки лимитов перед оплатой.

1. Распакуйте архив. Создайте GitHub-репозиторий и загрузите **содержимое папки `svoyak`**, сохранив папки. `package.json`, `Dockerfile`, `public`, `src`, `data` должны быть в корне репозитория. Сам ZIP вместо файлов загружать не нужно.
2. На https://railway.com создайте новый проект из этого GitHub-репозитория. Railway сможет собрать прилагаемый Dockerfile.
3. Оставьте **один экземпляр (replica)** сервиса. Это принципиально для корректной гонки кнопок.
4. Добавьте Volume с путём монтирования `/app/runtime`. В переменных задайте `DATA_DIR=/app/runtime`. Для прилагаемого Dockerfile также задайте `RAILWAY_RUN_UID=0`: по документации Railway том монтируется от root, а образ запускается от пользователя node. Альтернатива — заранее настроить владельца тома под UID 1000.
5. В настройках сети создайте публичный домен (Generate Domain). Приложение слушает `PORT`, переданный хостингом; без него — 3000.
6. Откройте HTTPS-адрес с телефона, создайте тестовую комнату и пригласите второй телефон.
7. При желании добавьте `PUBLIC_ORIGIN=https://ваш-домен` **без завершающего слеша**. Если используете несколько доменов, оставьте переменную незаданной.

Управлять созданным проектом можно в браузере телефона. Первичную загрузку файлов в GitHub тоже можно сделать с телефона, но нужно сохранить структуру директорий. После размещения личный ПК для игры не нужен.

Официальные страницы: https://railway.com/pricing · https://docs.railway.com/volumes · https://docs.railway.com/guides/public-networking

## Свой VPS / Docker

```sh
docker compose up -d --build
```

Приложение будет доступно на порту 3000. Именованный Docker volume `svoyak-data` сохраняет комнаты между перезапусками. Не используйте `docker compose down -v`, если хотите сохранить игры.
Для публичного доступа подключите домен и HTTPS через Caddy/Nginx. Для SSE отключите буферизацию прокси; тайм-аут чтения поставьте не менее 60 секунд. Пример location для Nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 90s;
}
```

TLS-сертификат и домен настраиваются отдельно. Если Nginx установлен на хосте, можно ограничить публикацию Docker-порта до `127.0.0.1:3000:3000`.

## Что изменилось в версии 1.1

Все 120 вопросов заменены: слова со скрытым КОТом, кино по плохим отзывам, выдуманные вывески, песни по эмодзи, бытовые двусмысленности, пословицы канцелярским языком, склейки персонажей, сказочные объявления, мультфильмы до 2016 года, ужасы, комедии, мемы, страны и города, спорт по инвентарю, а также задания «три за пятнадцать». Термины по физике, математические задачи и длинные анаграммы убраны.

У ряда заданий несколько допустимых ответов; у ведущего есть пояснения. В заданиях на перечисление засчитываются любые три правильных разных варианта, а не только примеры из подсказки.

При обновлении уже запущенной версии замените исходники между играми и создайте новую комнату: номера вопросов прежние, а содержимое другое.

## Как менять вопросы

Редактируйте `data/questions.json`. Сохраняйте два раунда, шесть категорий в каждом и пять вопросов в каждой категории — текущий движок рассчитан на этот формат.

```json
{
  "q": "Формулировка вопроса",
  "a": "Правильный ответ",
  "note": "Необязательное пояснение: допустимые варианты и ловушка"
}
```

На экране настройки ведущий выбирает длину партии: 30, 60, 90 или 120 вопросов. Каждому раунду соответствует 60 вопросов; игра автоматически закончится на выбранном количестве. Цена определяется позицией вопроса и раундом. Поле `note` видно ведущему и появляется у игроков после раскрытия ответа. Проверяйте анаграммы и однозначность ответов. Чтобы применить изменения, перезапустите/переразверните сервер **между играми**: сохранённые комнаты ссылаются на индексы вопросов текущего пакета.

## Технические особенности

- Node.js, стандартные модули, HTML/CSS/JavaScript без сборщика и внешних зависимостей.
- Команды отправляются POST-запросами, изменения приходят через Server-Sent Events. SSE открывается через fetch с заголовком Authorization, ключи не попадают в URL.
- Сервер принимает первое **доставленное ему** нажатие. При разных задержках сети это может отличаться от физического порядка касаний. Для честной игры предпочтительна стабильная общая Wi-Fi-сеть или сравнимое качество связи. Идеальная синхронизация через интернет не гарантируется.
- Сервер проверяет роль, фазу, номер ревизии и повторные попытки. Клиент не присылает сумму очков.
- Один Node-процесс, один экземпляр хостинга, локальные JSON-снимки с атомарной заменой файлов. Для горизонтального масштабирования понадобится общая БД и координация между процессами.
- Неактивные комнаты удаляются примерно через 24 часа после последнего изменения, если нет подключённых клиентов. До 200 комнат на процесс. Сохранения содержат ключи доступа: не публикуйте папку runtime.
- При перезапуске восстанавливаются абсолютные дедлайны: если время истекло, сервер применит соответствующий переход. Пауза таймера на время перезапуска не предусмотрена.
- Есть ограничения частоты запросов и размеров сообщений. За обратным прокси ограничения создания комнат/входа могут быть общими для всех пользователей. Проект рассчитан на небольшую компанию, не массовый публичный сервис.
- После начала новые участники не входят. Отключившийся игрок возвращается с прежним ключом из того же браузера; ведущий может закрыть вопрос без штрафа, если у отвечающего пропала связь.
- Нет встроенного голоса, аккаунтов, редактора вопросов и подключения физических кнопок. Кнопки — на экране каждого телефона.
- Без service worker: интернет нужен для игры; манифест не делает её офлайн-приложением.

## Проверка

`npm test`: 11 автоматических проверок, включая полное прохождение 120 вопросов, два конкурентных нажатия, новые длины партии 30/60/90/120, таймеры 30/30 секунд, повторы команд, запрет доступа игроку к скрытому ответу и сохранение после рестарта.
`npm run check`: проверка синтаксиса серверного и браузерного JavaScript.
Автоматический прогон интерфейса в Chromium выполнить не удалось: в среде отсутствовал браузер, а его загрузка завершилась ошибкой. Мобильная вёрстка подготовлена, но визуальная проверка на реальных iPhone/Android и в сети выбранного хостинга остаётся необходимой после развёртывания.
